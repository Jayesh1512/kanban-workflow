# AntSeed independent QA plan

Assignment: M0-Q. Owner: QA on `antseed/qa`. Requirements: [PROJECT_BRIEF.md](PROJECT_BRIEF.md), plus PM coordination updates dated 2026-10-17. This document defines acceptance; it does not report product tests as passed.

## Scope and independence

- M0-Q changes this document only. No product code, packages, composition, or competing contracts before the architect baseline. No extra chats, agents, or worktrees. PM integrates committed handoffs.
- After each integrated milestone, QA takes the PM-provided baseline into this branch, reviews shared contracts, adds independent tests/reproducers, exercises the running system, reports defects, and verifies owner fixes. Product fixes return to their owners.
- Expected results come from the brief and externally observable state, not from copying implementation branches. Tests drive public HTTP/MCP/operations entrypoints, read actual Vikunja state, and inspect persisted records where needed to establish recovery/idempotency.
- The proposed architecture locations are `src/shared/{domain,ports,schemas,api,lifecycle}.ts`, `db/migrations/001_initial.sql`, `src/platform/module.ts`, and `src/workflow/module.ts`. Signatures and transport details remain pending `docs/ARCHITECTURE.md`; QA must use the committed contracts rather than invent routes or tools. Architect/PM own composition.
- “Approved-only mutation” applies to backend/AI/Hermes lane movement after ticket creation. Normal ingestion, summaries, mapping corrections, actions, and dates follow their defined contracts; they do not implicitly authorize a lane change. No custom auth middleware, roles, sender allowlists, or app permission gates are acceptance requirements.

## Evidence and gate rules

Every scenario result records scenario ID, baseline/test SHA, UTC time, command or public interaction, input fixture, expected/actual result, and sanitized evidence locations. Record runtime/image/package versions, Compose project, and real versus substituted dependencies. Status is PASS, FAIL, BLOCKED (named prerequisite), or NOT RUN. A skipped live dependency never counts as PASS.

Evidence classes must remain separate:

- **Deterministic:** synthetic MTProto events, provider responses, clock, and controlled failure injection. Proves application behavior under those inputs only.
- **Real local integration:** actual PostgreSQL, pinned Vikunja, container build/bootstrap/restart, public HTTP server, and MCP protocol client. Specify any synthetic Telegram/model adapter still in use.
- **Real model upstream:** configured OpenAI and Vercel AI Gateway Jev calls with synthetic business text, bounded timeouts/retries, and sanitized response structure. A direct TypeSafe call does not satisfy the Vercel requirement.
- **Live Telegram:** actual `@mtcute/node` MTProto user login, account discovery, ingestion, control-group delivery/replies, reconnect, and persistence. Requires a configured account and relevant setup action. Never send to external companies; use designated test/control chats. Session files, codes, passwords, phones, and private history are not report artifacts.
- **Real Hermes:** Nous Research Hermes Agent connects to the backend MCP server. A generic MCP client proves protocol compatibility, but does not prove Hermes configuration or tool use.

P0: leaked credentials, unauthorized lane mutation, destructive cross-project action, or unrecoverable data corruption. P1: required workflow/recovery unavailable, silent loss, incorrect association, duplicates, incorrect board, or fake success. P2: lesser usability/diagnostic issues. Open P0/P1 defects fail their gate. An external prerequisite can leave a gate BLOCKED while independent tests continue; PM must not describe that gate or full release as passed.

Recheck all P0/P1 fixes and adjacent cases. - **A05 Crash matrix:** Terminate only the QA backend at each boundary: before proposal commit; after proposal commit/before delivery; after decision commit/before journal enqueue; after journal commit/before remote request; after remote accepted/before response; after response/before local applied commit; and after local applied commit/before acknowledgement. Final local/remote stage agrees; one logical movement, no lost approved work, and visible pending/conflict where outcome cannot be established safely. - **A06 Remote faults and worker races:** Inject actual/controlled Vikunja timeout, refused connection, rate limit, invalid credentials and service restart; race two apply workers on same journal. Counters and audits demonstrate one logical effect, not merely one HTTP response.
- **A07 Blocked/Archived/Completed behavior:** From an active lane, propose Blocked, approve, clear dependency and verify remembered previous active lane. Resumption needs another proposal/approval. Deliberate archive requires approval and remains visible, not deleted. Completed requires evidence of agreed outcome.
