# Outbound boundaries

Local app, SQLite and connectors run on the team's machine. General inference uses the official hosted OpenAI service; cross-swimlane judgment uses hosted TypeSafe Jev. [OpenAI choice](/Users/jys/Documents/Projects/hello/.context/decisions/2026-10-10-openai-cloud-llm.md) and [Jev choice](/Users/jys/Documents/Projects/hello/.context/decisions/2026-10-10-jev-swimlane-decisions.md) settle those destinations, not account risk, terms, privacy, quality, latency or cost. Neither hosted model is asserted open-source/self-hosted. Offline injected tests are [F] infrastructure checks, not a live-provider or [M] pass.

| Destination | Purpose and payload | Status |
|---|---|---|
| Telegram MTProto data centres | Read chats/messages/history/updates, session/login and account-owned listing. No observable chat write; asking for a login code is the sole permitted login effect. See [Connect Telegram](connect-telegram.md) for the installed-source audit, application profiles and limits of live observation. | Read-only connector; source audit and offline tests |
| `https://api.openai.com:443/v1/responses` POST only | General disposition, initial lane, card text/summary/contact/role/reference and same-lane stage proposals. Fixed system instruction; bounded third-party data in user blocks. No tools/uploads/provider conversation/previous-response loop. `store:false` is a request setting, not a retention guarantee. | Official SDK Responses adapter; strict structured output and guarded review |
| `https://api.typesafe.ai:443/v1/systemone` POST only | Jev movement-only model/state/questions. Scoped ticket title/summary (unless withdrawn provenance), configured lane/SOP/stages, every offered other-lane transition, retained permitted same-chat evidence and actual evidence-ID bundles. One independent movement plus stay support and support for EACH destination, selecting only the selected target's support. No generic card/contact generation or OpenAI fallback. | Hosted Jev adapter; bounded questions, validated answers and human movement review |
| `https://registry.npmjs.org` | Dependency acquisition/metadata during installation, separately from product operation/offline tests. pnpm installs integrity-pinned registry tarballs. | Install-only |

Both production bridges refuse redirects, query/fragment/userinfo/nondefault port/wrong host/path and pass bearer authentication only to the named destination. Native node:https uses no ambient HTTP proxy or credential configuration; SDK fetch strips other headers. No arbitrary endpoint, public-host switch, local inference or other-provider fallback. The historical private-overlay/100.64/allow-public policy is superseded history. OPENAI_BASE_URL and the four legacy MODEL_* endpoint/name/key/switch controls are rejected. A JEV_ENDPOINT value gives visibility, not permission to call another host. Test transports capture the canonical destination; no production loopback setting exists.

OpenAI configured model is server OPENAI_MODEL, unset until supplied; key is OPENAI_API_KEY. Settings shows api.openai.com, the configured model and a safe blocked reason, never keys. Missing model/key produces no inference request while human and ingestion work continue. General accepted limits: current+20 earlier same-chat messages,10 offered other-chat cards,15 companies;16384UTF8 bytes text+media per message,1MiB complete serialized request/response. The adapter and port enforce scoped context, request/response bounds and output structure. Default output4096/range1..16384, deadline30000ms/range1..60000, per-processing-attempt max2 calls/range1..2. Each decide sends one call; SDK retries0. Schema and transient retries share the per-processing-attempt call budget, with a1000ms injected wait and scheduled30s doubling to5min; this is not a two-call lifetime limit.

Jev configured model defaults jev-latest when selected; JEV_API_KEY is separate. Configured model, supplied resolved version and provider metadata remain separate from general-model status and replay execution; the app does not fabricate missing metadata. Accepted Jev limits:21 evidence messages,4096UTF8 bytes combined text+media per item;64KiB complete state,256KiB COMPLETE request (all questions/templates/options),1MiB response;<=253 transitions plus stay/review, exactly N+2<=255 questions,<=23 support options. Overflow is zero-call context_limit, with no truncation/shortlisting. The adapter and port enforce scope, question, option, state and body bounds plus the deadline. Default deadline10000ms/range1..30000, maxAttempts1/default or2/configured, retries only network/timeout/429/5xx using identical body/hash/questions and1000ms injected wait; total <= attempts*timeout+(attempts-1)*1000ms (max61000). No conditional second support call.

Ports support cancellation and discard late replies. The processing and review paths recheck transactional freshness and permissions, group typed failures and latch unsupported/authentication failures to prevent repeated calls or stale mutations. Request snapshot/hash stays immutable; the app stores separate expected POST-outcome settlement facts, IDs/versions/digests only, never request text/title/summary/raw provider errors. Accepted0002 audit is unchanged. No provider response cache is written. All real hosted authentication/integration, model quality/coverage/calibration, retention/latency/cost and [U] one-hour outbound observation remain untested.
